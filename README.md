# From Your Dream

**From Your Dream** 是一款由 AI 驱动的视觉小说创作与游玩项目。角色拥有各自的设定与记忆，在同一场景中听见玩家和彼此的发言，自行决定回应或沉默；玩家通过对话和行动影响剧情。

> 当前已有基于 Spring Boot、Spring AI 和 DeepSeek 的最小原型。通过已有 Redis 接口生成的字符串区分账号，游戏进度与历史先保存在服务进程内存中。

## 运行原型

需要 Java 17、Maven，以及现有两个接口可连接的 Redis。第一版不接入关系数据库，也暂不使用注册密码；生成的字符串就是演示账号 ID。

1. 在启动进程的环境变量中配置 `DEEPSEEK_API_KEY`。可以在 IntelliJ IDEA 的运行配置中填写，或在终端设置：

   ```bash
   export DEEPSEEK_API_KEY='填写你的 DeepSeek API Key'
   ```

   也可以在已被 Git 忽略的本地 `backend/src/main/resources/application.yml` 中新增以下配置，保留原有 Redis 配置：

   ```yaml
   dream:
     ai:
       api-key: 填写你的 DeepSeek API Key
   ```

2. 确认 Redis 配置。可以沿用本机的 `backend/src/main/resources/application.yml`；新环境默认连接 `localhost:6379`，也可通过 `SPRING_DATA_REDIS_HOST`、`SPRING_DATA_REDIS_PORT`、`SPRING_DATA_REDIS_PASSWORD` 配置。
3. 启动后端：

   ```bash
   cd backend
   mvn spring-boot:run
   ```

   也可以在 IDEA 中运行 `BackendApplication`。未安装命令行 Maven 时，可使用 IDEA 的 Maven 面板。

4. 在浏览器打开服务根路径，默认是 `http://localhost:8080/`；如果本地配置修改了 `server.port`，使用对应端口。
5. 点击“生成新身份”，或选择已有身份。开场事件和角色台词之后，直接呈现一个重大分歧与 2 至 4 个关键选项，每项说明不同的行动和取舍。选择后，AI 连续演绎人物回应、日常对白、行动与过渡，直到下一个重大决策点才交还操作权；也可展开“我有另一个决定”自由输入。当前故事最多 12 次关键决定，最后一幕结束后生成结局。

可选配置：`DEEPSEEK_BASE_URL` 默认 `https://api.deepseek.com`，`DEEPSEEK_MODEL` 默认 `deepseek-chat`。密钥仅在服务器使用。未配置密钥时仍可启动、管理身份和查看已有记录，发送新对话会提示配置模型。

示例故事位于 `backend/src/main/resources/demo-story.json`，可编辑故事背景、角色卡和决策预算；全局支持 1 至 20 次关键决定。`opening` 描写已自动演绎的开场事件，`openingPrompt` 配置开场角色和台词，`openingDecision` 配置 `question` 和 2 至 4 个 `choices`。每项选择包含唯一的 `id`、显示行动的 `label`、实际决定的 `action`、说明取舍的 `stakes`。`scenes` 按大纲顺序配置各幕的 `id`、`title`、`environment`、可出场的 `characterIds`、`goal`、`exitCondition` 和 `maxTurns`。各幕预算总和不能超过全局预算，第一幕的角色名单用于初始化在场者。可选的 `directorNotes` 保存导演独知的谜底、世界规则和揭示顺序，不会返回页面或加入角色的初始公共背景；后续生成仍需遵守实际证据和沟通渠道。

当前大纲根据用户提供的《剧幕之外》主线简介改编，玩家扮演夏玥，使用弹幕与《留白》中的白瑾互通信息。拆为 12 幕互动节点，并非对原剧逐集内容的复述：弹幕被看见 → 改路之后 → 重播不是重来 → 所谓安全的地方 → 片尾的名字 → 死亡时间正在靠近 → 门外的外卖员 → 王珊的破绽 → 两边交换线索 → 把线索连起来 → 最后一次改写 → 剧幕之外。每幕最多一次关键决定，日常对白和动作不单独占用次数；按有序大纲推进，最后一幕生成结局。开场不消耗决定次数。影片重播可以改变影片片段，现实时间和已经产生的现实后果不会回档。修改故事或模型配置后重新构建并重启服务生效。

### 这一版实现了什么

- 复用 `POST /api/redis/user-code` 生成身份，`GET /api/redis/user-keys` 选择已有身份。
- 页面通过 `userId` 请求参数区分账号，服务端也兼容 `X-User-Id` 请求头。支持 1 至 8 位字母或数字和 `user_` 前缀形式，并确认 ID 在 Redis 中存在；自动生成的身份仍为 8 位。
- 当前故事设定五个角色：玩家控制的现实女主夏玥、影片女主白瑾、白瑾的闺蜜与帮凶王珊、外卖凶手、白瑾男友周年。白瑾通过屏幕互动；周年在前期实际进入影片线调查或建立联络后可以回应，只知道白瑾实际转述及本人亲历的信息。王珊在影片线诱骗、困住白瑾，外卖凶手在现实接近夏玥，两人的行动通过叙事者呈现；夏玥不加入 NPC 名单。引擎仍支持零至多名在场回应者；角色可说话、只做动作或沉默。
- 同场公开说话由在场者听见；跨屏幕、电话、门两侧的认知按实际传递的信息约束。未在场角色不参与本轮生成，回来后也不会自动收到错过的交谈记录。当前跨渠道语义边界由生成指令约束，尚未实现通用的消息路由与时间回溯规则引擎。
- 每次玩家回合都有 2 至 4 个关键选项，包含行动与取舍。开场选项由作者配置，后续根据当前环境、人物设定和完整历史生成；选项必须对应不同的剧情方向，不拿普通应答凑数。
- 选项 ID 由服务端绑定到当前决策的实际行动，前端不能改写选项内容；历史保存当时的问题、所选行动与接受的风险，后续演绎、选项及结局均延续这些决定。
- 开场先呈现事件与角色的主动台词，无需选择交谈对象；开场也会显示在历史回看中。
- 完整历史独立保留，回看不调用模型；同一账号不同设备访问同一个服务实例时共享进度。
- 角色输出经格式校验后才更新状态。生成失败不保存半轮内容；同一请求重试不重复推进。
- `SceneEngine` 维护当前幕 ID、环境、在场名单、互动次数和结束状态；每轮由叙事者依据大纲和事件结算，代码校验目标幕、角色名单、所有见证者的记忆及时间上限。
- 叙事者落实玩家已选的方向，连续演绎必要的观察、联络、普通对白和玩家的小动作，到下一次重大取舍才停下。可以代写简短应答，但不能代替玩家表白、许诺未来、决定是否开门、是否信任或改变重大立场。
- 场景演绎、下一组关键选项、所有在场角色的记忆和全量历史一起提交；任一生成环节失败都保留上一组有效选项。每段历史保存 `witnessIds`，角色后续只读取自己在场时的近期事件；沉默角色同样记住听见的内容。
- 最后一幕结束时根据本局历史生成结局，未预置结局文案；目标失败、拒绝登台、未完成事项都能延续到后续幕与结局。
- 一个账号同时只处理一次推进；生成期间可以读取之前已经保存的历史。

进度、场景、记忆、去重记录和结局暂存在内存中，重启服务会清空，Redis 中的账号 ID 仍可继续使用。重新开始会清空该账号本局的游戏记录。场景结束条件、选项是否具有重大意义与自动演绎边界的语义判断由模型负责，代码负责大纲顺序、角色范围、预算、选项数量与字段、请求绑定和整轮提交；完整行动规则、分支大纲与持久化存档属于后续实现。

### 游戏 API

以下接口都需要账号 ID，页面统一传递 `?userId=账号ID`，避免预览或转发环境丢失自定义请求头。也可继续使用 `X-User-Id` 请求头；两种方式同时提供时值必须一致。返回格式沿用 `Result<T>`：

| 接口 | 用途 |
| --- | --- |
| `GET /api/game` | 获取当前账号的故事、角色、进度与历史 |
| `POST /api/game/turns` | 作出关键决定并演绎到下一决策点或结局 |
| `GET /api/game/history` | 读取已经保存的完整对话 |
| `POST /api/game/reset` | 重新开始当前账号的故事 |

选择请求示例，其中 `gameId` 和 `expectedTurn` 取自最新游戏状态：

```json
{
  "gameId": "从 GET /api/game 取得的 gameId",
  "requestId": "每次新决定使用唯一标识，重试时保持不变",
  "expectedTurn": 0,
  "choiceId": "redirect-now"
}
```

`requestId` 为 8 至 64 位英文字母、数字或连字符，建议使用 UUID。重复请求返回当前已保存进度；相同标识不能更换内容。旧页面的进度发生冲突时返回 `409`，刷新状态后再提交。重新开始请求体为 `{"gameId":"当前 gameId"}`。

请求无需 `characterId`。`choiceId` 必须来自最新 `decision.choices`，由服务端查找真实行动；或者省略 `choiceId` 并提供 `message` 表达另一个决定，两者不能同时填写。保留旧请求字段 `endConversation` 的解析兼容，但设为 `true` 会返回 `400`，不能让 AI 跳过玩家的重大决策。

未结束的游戏始终返回 `decision`，包含当前 `question` 和 2 至 4 个 `choices`；结局时为 `null`。每段历史额外保存 `decisionQuestion` 与 `selectedChoice`，自由决定的 `selectedChoice` 为 `null`。

返回的 `scene` 包含当前幕 `id`、`title`、`environment`、`presentCharacterIds`、本幕已作出决定的 `turns` 和 `ended`。每段历史的 `responses` 为零至多个角色回应，`witnessIds` 表示谁听见这段交流，`storyNarration` 保存回应之后的场景旁白。`sceneId`、`sceneEnded` 和 `nextSceneId` 记录该段是否完成了幕间转换。

## 体验目标

- **角色像角色，而不是问答机器人**：每个角色有自己的身份、性格、记忆、目标和表达方式。
- **剧情能自然延展**：角色可以根据上下文回应玩家，也可以在设定与故事边界内主动推动场景。
- **保留视觉小说的节奏**：以场景、立绘、背景、表情、旁白、对话框和选项呈现故事，而非只提供聊天窗口。
- **选择带来后果**：玩家的对话和行动会影响角色状态、关系和后续剧情，并在之后的场景中体现。
- **支持创作与扩展**：故事由可编辑的角色、场景、剧情规则和美术资源组成，便于增加新章节与角色。

## 核心体验

典型游玩流程：

1. 玩家进入一个故事或章节，了解场景与当前情境。
2. 角色 Agent 根据角色设定、已有记忆和当前场景生成台词或行动。
3. 玩家通过预设选项或自由输入作出回应。
4. 故事系统更新剧情状态和相关角色记忆，并决定接下来的场景发展。
5. 前端以立绘、表情、背景、文本和音效等视觉小说元素呈现结果。

玩家可以沿着作者设计的主线体验，也可以在允许的范围内自由交谈。剧情系统负责守住故事设定、角色边界和关键情节的一致性。

## 角色 Agent

每个角色由独立的 Agent 配置驱动。建议每个角色至少包含：

| 内容 | 用途 |
| --- | --- |
| 身份与背景 | 角色是谁，以及与故事世界的关系 |
| 性格与说话方式 | 决定角色如何表达、如何回应 |
| 目标与立场 | 角色想要什么，以及面对冲突时的倾向 |
| 当前状态 | 情绪、关系、所在场景和剧情进度等可变信息 |
| 记忆 | 记录对后续互动有用的共同经历与玩家选择 |
| 美术资源 | 立绘、表情、姿势、头像等角色素材 |

角色应只知道其设定和经历允许其知道的内容。故事规则、场景转换和结局条件由剧情层管理，避免单个角色的即兴回应破坏整体叙事。

## 视觉小说呈现

目标界面由以下元素组成，可根据故事逐步扩展：

- 场景背景与角色立绘
- 表情、姿势及角色出入场变化
- 对话框、角色名、旁白与可选的打字效果
- 预设剧情选项与自由输入
- 章节、路线、关系和剧情标记
- 存档、读档与回看对话
- 可选的音乐、环境音和音效

如果某个角色或场景暂时没有美术资源，体验仍应能以文字或占位素材继续进行。

## 设计原则

1. **先保证故事可控，再扩大自由度。** 重要剧情节点和结局条件应可验证；自由对话用于丰富过程。
2. **角色状态与故事状态分开管理。** 角色的即时情绪、长期关系和章节进度属于不同层次的信息。
3. **记忆服务于连续性。** 记忆应记录影响后续互动的事实，而不是无边界地保存所有对话。
4. **内容与呈现分离。** 角色、场景、选项和美术资源应能独立编辑，避免写死在界面逻辑中。
5. **模型输出需要结构化约束。** 对话之外的状态变化和场景推进应使用明确的数据格式，并由故事系统校验。

## 建议的 MVP

第一版聚焦一段完整、可重玩的短篇故事：

- 一个故事、少量场景和两到三个可互动角色
- 每个角色有独立设定、状态和有限的跨场景记忆
- 支持自由输入及作者提供的剧情选项
- 至少一个会影响后续内容的关系或剧情状态
- 支持立绘表情与背景切换；缺少素材时可用占位图
- 能完成一个章节并到达至少两种不同结果
- 提供最基本的存档或会话恢复能力

## 术语

- **角色 Agent**：以角色身份参与故事交互的 AI Agent。
- **故事状态**：影响场景、路线和结局的结构化剧情信息。
- **角色记忆**：角色为维持跨场景连续性而保留的互动摘要或事实。
- **演出**：背景、立绘、表情、音效和文本节奏等视觉小说呈现方式。
